# Choosing between similar tools

Read this when two Marcora tools look like they could both do the job: documents vs context items, briefs, editing, refreshing web pages, search vs browse, Brand Foundation, teams.

---

## Choosing between similar tools

| If the user wants… | Call this | Not this — because… |
|---|---|---|
| To write a new document (any kind) | Write it yourself from `marcora:get_relevant_context(team_id, prompt, include_brand_foundation=true)`, then `marcora:create_content` with `content` | `add_context` creates a *reference item*, not a document. Use `instructions` only when the user asks Marcora to write it, a Blueprint is used, or a plan is being fulfilled. |
| To generate from a template they name (or ask for) | `marcora:create_content` with `instructions` + `blueprint_uuid` | `get_blueprint` only fetches details; it doesn't generate. |
| To save text as a document (yours or the user's) | `marcora:create_content` with `content` only | Don't add `blueprint_uuid` or `instructions` — incompatible. |
| To pin a Content item as a project's strategic anchor | `marcora:update_project(team_id, project_id, project_brief_id=…)` | `add_context` creates a Context item, NOT a brief. Different objects. |
| To attach an existing Content item to a project (no brief intent) | `marcora:update_project(team_id, project_id, project_brief_id=…)` (which auto-attaches), OR have the user attach in-app | Don't `create_content(team_id, project_id=…)` to "duplicate" it into the project — orphaned copy. |
| To add reference material reusable across all projects | `marcora:add_context` (no `project_id`) | A Context Collection is just a folder; you still need `add_context` to put items in it. |
| To add reference material specific to one project | `marcora:add_context(team_id, project_id=…)` | `update_project(team_id, project_id, project_brief_id=…)` would make it the brief — only one of those per project. |
| To edit the name, content, or location of an existing context item | `marcora:update_context` | `add_context` would create a duplicate. Omit `collection_id`, `collection_ids`, `add_collection_id`, and `remove_collection_id` when you are only editing `name`, `content`, `import_url`, or `refresh_webpage` and want to keep the item's current collection memberships unchanged. To change collections: pass `collection_ids` to replace the full list (`collection_ids[0]` becomes the primary collection; `[]` moves the item to the Reference Library), `add_collection_id` / `remove_collection_id` to add or remove one collection, or `collection_id` for a single collection (`null` or `0` clears all collections). `project_id` is optional: omit it to keep the item's project; pass a project ID to move it, and `null` only when the user asked to take the item out of its project. Use `marcora:list_context_items` or `marcora:get_context_item` to inspect current `collection_ids` / `collections`. To replace the body from a URL with a one-off snapshot, pass `import_url` instead of `content` — backend extracts the markdown server-side. |
| To track a web page as context so it can be refreshed later | `marcora:add_context(team_id, connected_webpage_url=<url>)` | This creates a real `webpage` item with a stored, refreshable URL — `import_url` only takes a one-off snapshot that cannot be refreshed. Admin/Creator only; dedupes by URL. |
| To refresh a tracked web-page item after its source page changed | `marcora:update_context(team_id, context_item_id, refresh_webpage=true)` | Re-pulls from the stored URL (the app's refresh button). Only works on items created via `connected_webpage_url`. Find which items are refreshable via the `source_url` field on `list_context_items` / `get_context_item`. Don't `web_browse` + `update_context(team_id, context_item_id, content=…)` — that's a blind overwrite, not a tracked refresh. |
| To edit an existing Content document — change the body, name, stage (`ready` / `in_progress`), visibility, category, or single-project assignment | `marcora:update_content` | `update_context` operates on Context items, not Content documents — different object. `update_project(team_id, project_id, project_brief_id=…)` only changes a project's brief pointer, not the document body or fields. `update_content` is partial-update (omit a field = leave alone) and replaces the body in full when `content` is supplied — call `get_content` first if you need to splice into the existing markdown. Setting `name_override` LOCKS the title so it won't auto-resync from the body's first header on future edits. |
| To have Marcora's in-editor AI assistant edit / extend a document — or answer a question about it — with the reply streaming live into the document's sidebar | `marcora:ask_content_assistant` | `update_content` is a *manual* full-body replace — **you** compute and supply the new markdown. `ask_content_assistant` hands the request to Marcora's own Content Assistant: it loads the document + brand/reference context, decides whether to edit or just reply, and streams the result live to the user in the app. It's async — returns a `generation_id` to poll via `get_generation_status`. One run per document at a time: a second call on the same document fails until the first run finishes, so wait for a terminal status or combine requests into one `prompt`. It is NOT the general Marcora Agent. |
| To plan, generate, or review a proposed update to an existing document (from an update-mode plan, playbook step, or workflow) | `marcora:create_plan` / playbook step with `document_update`, `marcora:produce_plan`, and `marcora:list_document_updates` → `get_document_update` → `approve_document_update` / `discard_document_update` | `update_content` writes a full replacement body directly with no proposal/diff/approval step. Use `document_update` + `approve_document_update` when you want a diff-reviewed update tied to a plan, playbook cycle, or workflow (interactive conversations only; background runs cannot approve or discard). |
| To save a URL (blog post, competitor page, Google Doc export, presigned link) as a one-off context snapshot | `marcora:add_context` with `import_url=<url>` | Don't `web_browse`/`web_fetch` the URL just to paste the markdown into `content` — Marcora extracts the page itself and avoids the round-trip through your conversation. Use `connected_webpage_url` instead if you want the URL kept and refreshable (see the web-page rows below). |
| To read a project's brief (its premise and settled decisions) | `marcora:get_project` → `project_brief`, or the `project_brief` block on your first `marcora:get_relevant_context(team_id, prompt, project_id=…)` call; then `marcora:get_content(team_id, content_id)` when `truncated` is true | `update_project` only *sets* which document is the brief — it never returns the brief. `list_context_items` / relevancy search never surface it: the brief is a document, not a context item. |
| To know what content already exists about a topic | `marcora:get_relevant_context` for context, OR `marcora:list_content` for a content list | `create_content` would generate something new — wrong tool for "what already exists." |
| To browse what's in the user's context library (full inventory) | `marcora:list_context_items` | `get_relevant_context` returns the passages relevant to a question, not the item list. Use `list_context_items` for the catalog view. Pass `reference_library_only=true` to scope to just the top-level Reference Library. |
| To read the full markdown of a specific context item | `marcora:get_context_item(team_id, context_item_id)` | `list_context_items` only returns `content_intro` (a truncation). `get_relevant_context` returns matched passages. Use this to open one item whose ID you already have. |
| To find the passages in the library that are relevant to a question | `marcora:get_relevant_context` | It scores each passage on its own and against its whole document, drops weak matches and returns the top 10 with their `sources`. `list_context_items(team_id, search=…)` and `list_content(team_id, search=…)` only re-order a full listing: they cut nothing, so the response is as large as the library. Open a surfaced item in full with `get_context_item(team_id, context_item_id)`. |
| To read the team's Brand Foundation (company overview, brand voice, writing style, writing examples) | `marcora:get_brand_foundation` | `get_relevant_context` searches the Reference Library, not Brand Foundation. Auto-pulled into `create_content` when Marcora writes via `instructions`. When you write it yourself, `get_relevant_context(team_id, prompt, include_brand_foundation=true)` returns it together with the context in one call. |
| To change one of the four Brand Foundation elements | `marcora:update_brand_foundation` | Brand Foundation lives at the team level, not as Context items — `update_context` won't touch it. Always full-replace; fetch first with `get_brand_foundation` to confirm what's being replaced. Hand the user the returned `link_url` — never build a Brand Foundation URL yourself. |
| To list your teams (`team_id`), credits, or a teammate's numeric `user_id` (to assign a plan/content to them) | `marcora:get_current_user_info` | Returns your profile plus `teams[]` with every enabled team's `team_id` (to pass on calls), `your_role`, Studio Credits, plan, and full `members[]` roster — the value `assigned_to` / `update_plan(team_id, plan_uuid, assigned_to=…)` expects. Pending invites show `user_id: null` (can't be assigned yet). |
| To find out which share links were opened, who a link was created for, or inspect one link's viewers and opens | `marcora:get_share_link_activity(team_id, share_link?)` (pass `share_link` URL/token for one link's detail; omit `share_link` for list mode with `filter` / `query`) | Don't open the share URL yourself to check: that would record an open. On paid plans, each returned link includes `recipient_name` and `recipient_email` (`null` when unset) for who the link was created for. `opened` / `opens` are the lifetime counter; an empty viewer list or log with `opened: true` means older opens without details (`opens_without_details`, `coverage_note`), never "not opened". Viewers are anonymous numbers, not people: don't tell the user a named recipient opened it. Automated opens are excluded from the counts. |
| To save or edit a standing rule for how Marcora processes future calls (recurring transcription word fixes, or guidance steering what Marcora suggests from calls) | `marcora:list_call_instructions`, `marcora:add_call_instruction`, `marcora:update_call_instruction`, `marcora:remove_call_instruction` | `add_context` (`as_call` or `import_from`) saves a specific call transcript, not a standing rule. Standing call instructions apply to calls processed from now on (all calls by default, or one `automatic_call_import_id` from `list_call_instructions`); use `update_call_instruction(team_id, instruction_id, enabled=false)` to pause one without deleting it. |
| To find or browse curated Sales Enablement Hub documents and give the user their reading-page links | `marcora:find_enablement_documents(team_id, query?, category_ids?, limit?)` | `get_relevant_context` searches Reference Library/collections, not Enablement Hub categories or `internal_only` tags. Omit `query` to browse categories and their documents; pass `query` for ranked title/category/body matches. `limit` (1–50, default 25) caps ranked documents in search mode and total category placements plus uncategorized docs in browse mode — if `has_more` is true, narrow with `category_ids` or `query` (no offset). Present `link_url` as returned and flag `internal_only: true` docs as workspace-only. (Only listed when Enablement is on for a team.) |
| To publish a document to a connected app destination (Google Docs, Notion, etc.), update all published copies, or link an existing copy | `marcora:publish_content` | `run_workflow` refuses publish destinations, `create_external_share` makes a public Marcora share link, and destinations can only be set up in the Marcora app — not over MCP. Call `mode: "status"` first to see `workflow_id` destinations and `is_private`/`is_owner`. |
| To act in a specific team (or across multiple teams in one session) | Pass `team_id` on each team-scoped tool call (get `team_id` from `initialize` instructions or `marcora:get_current_user_info`) | There is no global active-team switch tool: passing `team_id` scopes only that call and never changes open Marcora app tabs or other sessions. |
